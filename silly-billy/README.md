# Silly Billy

A 3D room full of people, a cat and things, seen from high up like Castle Builder. A child holds the big button, calls an avatar by name and says what to do, in Finnish or in English as the pause card is set: "Aino, heitä pallo Eetulle". What the game already knows happens at once. What it does not know yet, Claude works out while the avatar stands thinking it through under a cloud of turning cogs: an interpreter (Opus, quick at low effort) understands the words and sketches any new thing, and a designer (Opus again) writes the new action or thing as code. The code is tested in a sandbox, joins the library on disk, and the next time it is instant. New avatars are made and dressed the same way: "tee uusi tyttö", "anna hänelle iso kihara tukka niinku Gabbylla", "anna hänelle vaaleanpunainen iltapuku", "anna hänelle taikasauva".

The brief is Sami's [`design.md`](design.md); the decisions, the engine's rules and what is still open are in [`plans/silly-billy.md`](../plans/silly-billy.md).

```
npm run dev                     # https://$DEV_HOST:3002/silly-billy/ (the dev server is what invents)
npx vitest run silly-billy      # the engine, the built-ins, the parser, the brain on a fake link, the sandbox, the server with a fake CLI
npm run build                   # the static build plays the library it ships with and invents nothing
```

## What it needs

- **The Claude Code CLI** on this computer, signed in to Sami's subscription: the dev server runs it with no tools, from an empty folder, one process per question. It is found on the `PATH`, in the desktop app's folder (`~/.config/Claude/claude-code/`) or in the VS Code extension; `CLAUDE_BIN` names it outright.
- **Whisper** for the child's voice: Silly Billy's own whisper.cpp build under `~/src/silly-billy-whisper` (made by its `setup.sh`: whisper.cpp 1.9.5 with a request field that keeps letters the language does not write out of the words, and Finnish-NLP's Finnish fine-tune of large-v3), else belay-that's build and large-v3-turbo under `~/src/belay-that/vendor`; started by the dev server on port 8179 the first time the page opens. It hears the language set on the pause card, primed with the names of who is here. Without it the browser's own recognizer listens (Chrome and Safari, `fi-FI` or `en-US`), and the type box is always there. On a tablet or a phone the microphone records without the phone-call processing (echo cancelling, noise suppression, gain), which squashed a child's high, quiet voice, and a clip with no voice in it is heard as nothing rather than as Whisper's 'Kiitos!'. A change to the dev server's code takes effect on the next request, with no restart (Whisper starts afresh too).

## How to play

| Do | What happens |
|---|---|
| Hold the big button (or Space) and talk, let go | The words show above the button as they are heard; on letting go the command goes. |
| "Aino, hyppää" ("Alice, jump" in English) | Aino jumps. A name first, then what to do; "kaikki" or "everybody" is everybody. Without a name, the last one spoken to (or the face last tapped) does it. |
| "Ei!", "ei ei ei", "älä!" ("No!" in English) | The last one spoken to stops what it was just told ("Aino, ei!" stops Aino). "Seis" or "kaikki seis" stops everybody. Said with more ("Mikko, mene vessaan ja älä vedä vessaa", "lopettakaa leikkiminen ja Mikko, tule tänne"), whoever it is said to stops at once (everybody for "lopettakaa") and the interpreter plans the rest. |
| Tap a face in the row at the top | The next command without a name goes to them, and the camera goes to them as they wave. Tap the lit face again to let them go: nobody is spoken to, and the camera goes back to the whole room. |
| "Aino, heitä pallo Eetulle" (the first time) | The interpreter understands it in 3 to 7 s. Aino says "Hmm, mietitäänpä!" in her bubble and aloud (in English, Alice says "Let me think this through!") and thinks under a cloud of cogs that fills up as Opus writes, for about 10 s more; then she says her answer and throws. The next time it is instant. |
| "Eetu, aja pyörällä joulukuusen yli" | A rough bicycle and Christmas tree pop up at once, Eetu thinks, and about 20 s later the real ones replace them with a sparkle and he rides over the tree. |
| "Mikko, tee kärrynpyörä", "anna Nooralle kruunu" | A new move (a cartwheel, measured 14 s from the words) or a new thing to wear (a crown, 11 s): anything the game does not know yet is made the same way. |
| "Aino, hyppikää trampoliinilla ja tehkää voltti siellä", "siirrä vesiliukumäki lammen päälle", "vaihda yöksi ja sytytä lamput" | Something for just now that no known move does exactly: the interpreter writes a few lines of code for this moment with its plan (or Opus does, while the avatar thinks), it is tried in a copy of the world, played once and forgotten. An avatar gets up onto a thing's top and stays there for jumps and flips; a thing of any size is moved (carried, pushed, or by magic when it is built in or goes up onto another), and anything or anyone goes along any route at any pace, whoever rides or stands on a moving thing going with it; anything can be ridden or stood on (silly is the point), and what cannot be done as asked is done the way it can; the night falls over a few seconds and the lamps light up what is near. |
| "Eetu, tee puumajaan tikkaat", "Noora, rakenna liukumäki puumajasta" | Something made for another thing is new and fixed to it at its side or top, sized to reach up to its floor when it leads there, and goes where that goes. What is made or built is always a new one: the slide already in the playground stays as it is. |
| "Mirri, syö sieni", "Noora, ui", "sataa lunta" | What things are and the world's weather matter: the red mushroom is poison and makes Mirri sick a while (green, slow, and better after a little lie-down), water makes one wet, snow cold, a fire warms; the pool can be emptied and filled. |
| "tee uusi tyttö", then "anna hänelle ..." | A new girl joins with a name of her own (Ella, or Olivia in English, unless the child gives one); "her" is the newest one. What she is given becomes part of her look and stays; what she wore there before goes in a sparkle. |
| The room buttons, or "mennään metsään" | The playground, the swimming pool, the forest. Each room keeps its things. |
| "Leikitään hippaa", "Aino ja Eetu pelaa jalkapalloa" | A game together: tag, football, hide and seek, a race or a train, for everyone or for those named. The first one named starts it and is "it", the seeker or the train's front. It lasts half a minute or so; "kaikki seis" stops it, and a new command to one player takes that one out. |
| The type box under the room buttons | Type a command and press Enter or the arrow: the same as saying it. While it has the keys, Space is a space, not the talk button. |
| Pinch, the mouse wheel, or the + and − buttons | Zoom in to see the avatars up close, out to see the whole room: out always works, even while the camera is close on someone busy, and stays out until a new command or a face is tapped. Zoomed in, drag to look around; a double tap goes back to the whole room. |
| `Esc` or the pause button | Pause: keep going, sound, voices (the avatars answer aloud in the game's language), Suomi (the default) or English: everything shown, said and heard follows it, and the starting avatars are Aino, Eetu, Mikko, Noora and Mirri in Finnish, Alice, Steve, Mike, Nora and Luna in English; forget the newest thing or everything made (each taps twice; only with the dev server), full screen, more games. |

The camera stands back to show the whole room, Castle Builder's view, unless the child zooms in (as far as 2 m of ground across the screen; only for the visit). When someone does something it moves in on them, on who and what their command names and on anything still flying, and goes back out 2.5 s after the last one stops; when a made thing's real model replaces its rough one, the camera shows it up close for 3 s. Heights count: up on a roof the camera rises with them and frames them as on the ground; a tall thing a command names, or someone high up with someone below, is framed with its top on the screen; and the whole room widens while anything in it would reach over the top of the screen.

At the top left, the line heard and how long understanding took ("ymmärretty 3,2 s", in English "understood 3.2 s"), and a card for each thing being made with what is happening and for how long: "Mietitään: kärrynpyörä 12 s", "Piirretään: kruunu", "Kokeillaan", "Yritetään uudestaan" ("Thinking this through: cartwheel 12 s", "Drawing: crown", "Trying it out", "Trying again"). If the microphone is refused or missing, the big button shows a crossed-out microphone and "Ei mikrofonia" ("No microphone"), and the type box glows to show where to type; with nothing to listen at all, there is no big button and the type box glows ("Kirjoita, mitä tehdään", "Type what to do"). On a phone the faces get the whole top row. On an iPad the first touch turns on the sound and the voices.

The name tags and speech bubbles stay beside their owners and on the screen, and keep their side as people move; in a thick crowd the nearer one covers the farther. The voices speak the game's language and take turns: lines said at the same moment are heard one after another, each avatar in its own voice ("aino ja eetu sanokaa hei" is two hellos). A browser with no voice for the language says nothing.

The game waits at most 45 s for the interpreter and 90 s for a new thing or action (both tries together); past that whoever waited shrugs, so a child is never left waiting for something stuck. When the page stops waiting, the dev server stops the model too.

Misheard words are part of the fun: the game always does something with what it heard, the closest-sounding avatar answers, and nobody ever gets hurt (a hit is a bonk, a tumble and a giggle).

## The built-ins

- **The cast**, called by the game's language: Aino / Alice (a ginger ponytail, purple top), Eetu / Steve (a red cap, blue shirt), Mikko / Mike (a tall grown-up with glasses), Noora / Nora (blonde pigtails, pink dress) and Mirri / Luna the orange cat. Made avatars join them and stay, named from a list for each language (Ella, Leo, Venla...; Olivia, Jack, Hannah...) unless the child names them; their names, and any name the child gives, stay in both languages.
- **The basic verbs**: walk, run, come, pick up, drop, give, jump, wave, sit, sleep, spin, say, follow, look, make (a new one, also made for another thing and fixed to it), remove, wear, take off, paint, grow, shrink, rename. Throwing, riding, dancing, swimming, climbing, eating and everything else is invented the first time it is asked for; what a made action picks up it puts down nicely when it is done, unless keeping it is the point.
- **The world**: the sky (the time of day, night with the moon and stars, rain, snow, fog and wind), each room's water (the pool and the pond, which can be emptied and filled) and ground colour; the states a body shows (sick, dizzy, wet, cold, sleepy, hot, glowing); things fixed to other things or to someone, shapes added to one thing (a window on this house), a part painted, hidden or lit, lamps and fires switched on and off and lighting what is near at night.
- **The group games**, for several avatars together: tag (hippa), football (jalkapallo, with a red and a blue goal put up for the game), hide and seek (piilosta), a race (kilpajuoksu, a swimming race in the pool) and a train (juna, follow the leader).
- **The rooms and their things**: the playground (slide, swings, seesaw, sandbox, climbing frame, roundabout, benches, trees, balls), the swimming pool (the pool to wade and float in, diving board, loungers, parasols, swim rings, a beach ball, rubber ducks, palms) and the forest (pines, rocks, logs, stumps, big red mushrooms, a tent, a campfire, a pond).

## The library

Everything made lives in [`library/`](library/): `items/<id>.json`, `actions/<id>.json`, `avatars/<id>.json` (a made avatar, or a starting one whose look changed) and `phrases.json` (words heard before and what they meant, so the same words need no model at all; each phrase remembers which interpreter prompt made its plan, and after a change to the prompt the words are understood afresh; words that point ("hän", "hänelle", "heille", "se", "sille", "toiselle", "molemmille", "kaikki") are not kept, since they mean someone else the next time; a phrase is kept only once every thing it uses was saved and only if it would play as it is, and a plan cut short by newer words is not kept). A plan's script (code for that moment only) is never kept, and words that made one are understood afresh the next time. The voice clips the page sends are kept in `library/voice/` (not in git; see For the parent). A made action names no kind in its code: what it uses and what comes out of the thing used come in by its params (the bow's arrow, the cannon's snowball), filled from what the interpreter knows of those things. Each entry keeps the child's words that asked for it, the designer's code and the guarded code the page runs, and its name in Finnish. The dev server reads the folder back when it starts, so a reboot keeps everything, and the build ships it, so what was made at home plays on the hosted page too. Reading it brings a library from before the game had two languages up to date: an action or a thing takes its first Finnish word as its Finnish name, and the phrases from then are dropped (their words are understood afresh). `library/log.jsonl` (on the laptop only and git-ignored, since it holds the children's words) logs every command, plan, invention, test and timing. Two pages open on the one dev server (two children, two tablets) share the library as they play: what one makes or forgets, the other has at once, so nothing is made twice. "Forget the newest thing" on the pause card removes the newest made thing and the phrases that used it; deleting a file by hand removes anything older, and words that used it are then worked out afresh.

## How new code is kept safe

The designer writes plain JavaScript against the engine's small API ([`src/engine/apidoc.ts`](src/engine/apidoc.ts) is exactly what it is told). Generated code never runs in Node on the laptop. The walls round it, outermost first:

- **Scripts** (a plan's code for this moment, from Haiku or Opus) go through the same walls as made actions: the guard on the dev server, the test in a throwaway worker, and the play-time checks.
- **The guard** ([`src/server/guard.ts`](src/server/guard.ts)), on the dev server: the code is parsed and refused, like a syntax error with the designer's line, if it names anything but its own names, its params and a few plain built-ins (Math, JSON, Array, Object, Map, Set, ...), reaches for keys like `constructor`, `prototype` or `__proto__`, or calls `import()`. Keys worked out at run time are checked as the code runs, and a refused one names its line. A guard call goes into every loop and function, so a loop that never yields is stopped. The code is guarded afresh when it is saved and when the library is read (a file guarded by an older guard is rewritten); the tests read the library the same way before every build, so a commit ships today's guarded code, and they fail on an entry the guard refuses.
- **The test**: the page runs new code first in a throwaway Web Worker against a copy of the world, for up to 20 game seconds and killed after 4 real ones, an action also with its optional args left out, a thing's process lying about and, if it can be worn, worn, within the time it gets in play. An error goes back to the designer once to fix; a thing that works but lost some of its shapes plays at once and goes back once with what was lost. Only code that passed is saved.
- **At play time**: strict mode with the page's globals shadowed; an action or a thing's process that takes too long in real time is stopped (the action ends with a shrug, the process is taken away); every error ends the action with a shrug; every number it writes is made finite and kept inside the room. One gap is left: a single huge call into the browser itself (an array of a billion) can still hold the page once.
- **The dev server's API** answers only the game's own page: a request from a page of another site gets a 403.

## For the parent

| Setting | Does |
|---|---|
| `?say=Aino, hyppää` | Hears these words when the game starts (repeat it for several). `window.game.hear(text)` does the same from the console. |
| `SILLY_LIBRARY=<folder>` | The dev server keeps the library there instead of `silly-billy/library/` (for trying things out without touching the real one). |
| `SILLY_INTERPRET_MODEL`, `SILLY_INVENT_MODEL` | The models for understanding and for inventing (`opus` and `opus`; `SILLY_INTERPRET_MODEL=haiku` or `sonnet` for a quicker first word or less of the weekly limit, measured in `plans/silly-billy.md`). |
| `SILLY_WHISPER_BIN`, `SILLY_WHISPER_MODEL`, `SILLY_WHISPER_PORT` | Another whisper.cpp server, model or port. |
| `CLAUDE_BIN` | The Claude Code CLI to run. |
| `node silly-billy/tools/mark.mjs` | Plays each kept voice clip (`library/voice/`, the newest 3000 or 1.5 GB, not in git) and asks what was really said and who said it (3, 5 or the adult). |
| `node silly-billy/tools/bench.mjs` | Runs the kept clips through the candidate recognizers and settings (on its own Whisper, port 8199) and writes a report in `library/voice/bench/`: letters, loops, inventions, words known, the right avatar named and, for marked clips, how many characters and words were wrong. |

The rooms (what lies where) are kept in the browser's `localStorage` under `silly-billy-rooms-1` and the settings (sound, voices, language) under `silly-billy-settings`; the avatars and everything made are kept in the library.
